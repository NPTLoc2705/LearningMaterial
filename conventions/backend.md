# Backend Architecture & Conventions (`Ielts-System/`) — REFERENCE ONLY

> **NOTE (Reference Only — `Ielts-System`)**: Kept as historical reference. For the Junior English Learning Platform (`server/LearningPlatform/`, `LearningPlatformDbContext`), see [conventions/learning-platform-backend.md](learning-platform-backend.md) and [docs/platform/02-architecture.md](../docs/platform/02-architecture.md).

> **Scope**: Primary backend solution (`Ielts-System/`), a 5-layer .NET solution.  
> **Dependency Rule**: Read top-to-bottom. Each layer only references layers below it.

```
Ielts_System (API)  ->  Service  ->  Repository  ->  DAL  ->  BusinessObject
```

---

## 1. Layer-by-Layer Rules

### Layer 1 — `BusinessObject/`
- **Contains**: EF Core entity classes, enums, and DTOs.
- **Naming**: `PascalCase.cs` matching the domain noun (e.g., `User.cs`, `Payment.cs`).
- **Sub-folders** for features with multiple related classes: `Admin/`, `Payments/`, `Quiz/`, `Referral/`, `UserProfileEnum/`, `evaluation/`.
- **DTOs** live in `BusinessObject/Dtos/{Feature}/` (e.g., `Dtos/Payment/`, `Dtos/Auth/`).
- **Strict Rule**: No business logic, no EF queries. Pure data shapes only.

### Layer 2 — `DAL/` (Data Access Layer)
- **Contains**: `WritingAiHubDbContext.cs` (single DbContext) and DAO classes executing raw/complex EF queries.
- **Naming**: `{Entity}DAO.cs` (e.g., `UserDAO.cs`, `PaymentDAO.cs`). The interface pattern is **NOT** used at this layer.
- **Sub-folders** for feature groups: `PaymentsDAO/`, `Moderator/`, `QuizDAO/`, `ReferralDAO/`.
- **Migrations**: `DAL/Migrations/` — auto-generated by EF Core. Never hand-edit migration files.
- **Strict Rule**: DAO classes take `DbContext` directly. No HTTP context, no service interfaces.

### Layer 3 — `Repository/`
- **Contains**: Repository interfaces (`I{Entity}Repository.cs`) and implementations (`{Entity}Repository.cs`).
- **Naming suffix**: `Repository` (concrete) / `IRepository` (interface). **Not** `Repo` for new concrete classes (see [known-inconsistencies.md](known-inconsistencies.md)).
- **Sub-folders** mirror DAL sub-folders: `PaymentRepo/`, `Moderator/`, `QuizRepo/`, `RatingRepo/`, `ReferralRepo/`, `Roadmap/`, `TaskList/`, `Teacher/`, `Writing_task1/`, `Writing_task2/`, `AvarageScore/`, `Evaluate/`.
- **Strict Rule**: Repositories call DAOs; they do not contain business logic or HTTP context.

### Layer 4 — `Service/`
- **Contains**: Service interfaces (`I{Feature}Service.cs`) and implementations (`{Feature}Service.cs`).
- **Naming suffix**: `Service`.
- **Sub-folders** mirror feature areas: `PaymentsService/`, `Moderator/`, `QuizService/`, `RatingService/`, `ReferralService/`, `Roadmap/`, `Storage/`, `TaskHistories/`, `Teacher/`, `Writing_task1/`, `Writing_task2/`, `AverageScore/`, `Evaluate/`, `FileUpload/`, `JWT/`.
- **Top-level service files** (not in sub-folders): `UserService.cs`, `UserCalendarService.cs`, `EmailSender.cs`, `CalendarReminderService.cs`, `SubscriptionExpiryService.cs`, `OtpCleanupService.cs`.
- **Strict Rule**: Services call Repositories only (not DAOs directly). All business logic lives here.

### Layer 5 — `Ielts_System/` (API Project)
- **Contains**: ASP.NET Core controllers, middleware, `Program.cs`, and `appsettings.json`.
- **Controllers** live in `Ielts_System/Controllers/`. Feature-grouped controllers use sub-folders: `Payments/`, `Moderator/`, `Teacher/`, `Referral/`, `MiddleAI/`.
- **Naming suffix**: `Controller`.
- **Middleware** lives in `Ielts_System/Middleware/`.
- **Strict Rule**: Controllers inject `I{Feature}Service` only. No DAL or DAO references. No business logic in controllers.

## 2. Where New Files Go — Backend Cheat Sheet

| What you're adding | Where it goes | Naming example |
|---|---|---|
| New entity / domain object | `BusinessObject/{Feature}.cs` OR `BusinessObject/{Feature}/` if grouped | `Classroom.cs` |
| New DTO | `BusinessObject/Dtos/{Feature}/{Dto}.cs` | `Dtos/Payment/PaymentRequestDto.cs` |
| New EF query (DAO) | `DAL/{Feature}DAO.cs` OR `DAL/{FeatureGroup}/{Feature}DAO.cs` | `DAL/PaymentsDAO/PackageDAO.cs` |
| New EF migration | `dotnet ef migrations add ...` — output goes to `DAL/Migrations/` automatically | — |
| New repository interface | `Repository/{FeatureGroup}/I{Feature}Repository.cs` | `Repository/PaymentRepo/IPackageRepository.cs` |
| New repository implementation | `Repository/{FeatureGroup}/{Feature}Repository.cs` | `Repository/PaymentRepo/PackageRepository.cs` |
| New service interface | `Service/{FeatureGroup}/I{Feature}Service.cs` | `Service/PaymentsService/IPackageService.cs` |
| New service implementation | `Service/{FeatureGroup}/{Feature}Service.cs` | `Service/PaymentsService/PackageService.cs` |
| New API controller | `Ielts_System/Controllers/{FeatureGroup}/{Feature}Controller.cs` | `Controllers/Payments/PackageController.cs` |
| New middleware | `Ielts_System/Middleware/{Name}Middleware.cs` | `Middleware/RateLimitMiddleware.cs` |
| Background/hosted service | `Service/{Name}Service.cs` (top-level, implements `IHostedService`) | `OtpCleanupService.cs` |

## 3. Dependency Injection (DI) Registration

All services, repositories, and DAOs must be registered in `Ielts_System/Program.cs`.

```csharp
// Pattern:
builder.Services.AddScoped<I{Feature}Repository, {Feature}Repository>();
builder.Services.AddScoped<I{Feature}Service, {Feature}Service>();
```

---

## 4. Backend Anti-Patterns (Never Do These)

- **Do not** call a DAO directly from a Controller or Service constructor — always go through the Repository layer.
- **Do not** put business logic (calculations, validation, orchestration) inside a Controller — it belongs in Service.
- **Do not** put complex EF query logic inside a Repository — it belongs in the DAO.
- **Do not** add HTTP-aware code (`HttpContext`, `IHttpClientFactory`) inside Service, Repository, or DAL layers.
- **Do not** reference `Ielts_System` (API project) from any other layer — the dependency only flows inward.
- **Do not** add new entity classes directly to `DAL/` — entities belong in `BusinessObject/`.
- **Do not** hand-edit files in `DAL/Migrations/`.
